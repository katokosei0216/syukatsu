# 進め方・役割分担・デモ台本(5人 / 8〜12時間)

## 3フェーズ進行(スライドどおり)

| フェーズ | 時間 | 場所 | やること |
|---|---|---|---|
| 第1: 合流 | 1〜2h | 1台のPC | 環境構成決定・共通テーブル定義の固定・ステータス文字の共有(このリポジトリの雛形がほぼ完成済みなので確認+微修正) |
| 第2: 分散 | 4〜6h | 各自のPC | 機能縦割りで実装。**AIプロンプトに docs/common-definitions.md を必ず貼る** |
| 第3: 合流 | 2〜3h | 1台に再集結 | 結合テスト・データ連携検証・発表スライド作成 |

## 役割分担

| 担当 | 担当ファイル | やること |
|---|---|---|
| 統括&DB基盤(1名) | `main.py` / `db.py` / `seed.py` / スライド骨子 | 進行管理・共通定義の維持・ダミーデータ・発表スライド |
| 担当A(学生チーム) | `routers/req01_companies.py` + `templates/req01_companies.html` | 志望企業登録・状況更新 |
| 担当B(学生チーム) | `routers/req02_memos.py` + `templates/req02_memos.html` | 選考メモ・振り返り記録 |
| 担当C(教員チーム) | `routers/req03_dashboard.py` + `templates/req03_dashboard.html` | 進捗ダッシュボード |
| 担当D(教員チーム) | `routers/req04_student_detail.py` + `templates/req04_student_detail.html` | 学生詳細・指導メモ |

## 分散フェーズの進め方(各自)

1. 自分の担当機能の**現状コードを先に読む**(雛形が最低限動く状態で入っている)
2. 改善したい点を決める(例: 検索・ソート・確認メッセージ・見た目)
3. AIに指示するときは「共通定義+現状コード+やりたいこと」をセットで渡す
4. 動作確認は `uvicorn main:app --reload` で各自ローカル確認
5. 迷ったら30分で切り上げ、統括に相談

## 任意機能候補(必須4つが完成してから、1〜2個)

- ☐ 直近1週間の面接予定・締切のリマインド表示(REQ-03 or トップ画面)
- ☐ 要フォロー学生アラート(応募0社・2週間停止をハイライト)
- ☐ クラス就活統計グラフ(Chart.js / 手書きCSSバーでも可)
- ☐ **AI面接アドバイス連携**(OllamaでローカルLLM: 反省メモ→改善アドバイス生成)※既にPCにOllama+qwen2.5-coderがあるので実績あり
- ☑ 初期ダミーデータ生成(`seed.py` で実装済み)

## デモ台本(10分: 発表7分+質疑3分)

1. **概要(1分)**: 課題・対象ユーザー(学生/教員)・技術構成(SQLite+FastAPI+HTML、完全無料・ローカル)
2. **実機デモ(3分)**: 学生として企業登録→ステータス更新→メモ記録 → 教員側ダッシュボードに反映されていることを見せる(データ連携デモが一番説得力ある)
3. **AI開発の比較(2分)**: 良い点(速度・雛形の質)/悪い点(結合時のキー名不整合・勝手に機能を削る・同じ説明を繰り返す)
4. **改善点と所感(1分)**: 「共通定義を最初に固定したから破綻しなかった」「丸投げは失敗した、小分け指示が有効」など
