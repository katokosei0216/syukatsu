# 教員側デモ台本(発表会用)

対象: 教員側担当(REQ-03 / REQ-04)
想定時間: 6〜8分(学生側の入力デモを含める場合は+1分)

## 0. 事前準備(発表前に必ず)

```bash
# 1. ダミーデータを入れ直す(前回のデータが残っている場合)
#    app.db を削除してから実行する
py seed.py

# 2. 起動
uvicorn main:app --reload
```

- http://localhost:8000 を開き、トップ画面を表示した状態にしておく
- ブラウザのズームは100%に合わせる
- AIを見せる場合のみ、`.env` に `OPENAI_API_KEY` を設定してから起動し直す
- `seed.py` は**要フォロー2名・未活動1名・内定者・直近7日の予定**が必ず出るように作ってある

## 1. トップ画面(30秒)

- 学生と教員、2つの役割があることを説明
- 「ローカルで動く・無料・DBはSQLite」という構成に触れる

## 2. 学生側の入力(1分)

1. `/req01` で企業を1件登録し、ステータスを「応募済み」に変更
2. `/req02` で選考メモを1件追加

> 「この入力が、このあと教員側にそのまま反映されます」と予告する。

## 3. 教員ダッシュボード(1分30秒) `/req03`

見せる順番:

1. 上部の集計カード(クラス人数 / 内定者 / 活動中 / 要フォロー / 未活動)
2. 選考ステータス別の棒グラフ
3. **要フォローアラート**(14日以上動きがない学生) ← 必須要件2の中心
4. 直近7日の予定(面接・締切・指導)
5. 「要フォロー」タブで絞り込み、学生名検索も一瞬見せる

> 「全員の状況を1画面で把握でき、動きが止まっている学生は自動で浮き上がります」

## 4. 学生詳細と指導メモ(1分30秒) `/req04/{学生ID}`

1. 要フォローの学生(高橋04 または 小林09)を開く
2. 活動サマリー、応募企業、選考メモ、次回選考を確認
3. 指導メモをカテゴリ「履歴書」・次回指導日つきで保存
4. カテゴリタブで絞り込み、編集・削除も見せる

> 「履歴書添削や面談の記録を、カテゴリと次回指導日つきで残せます」← 必須要件3

## 5. AI面接アドバイス(1分30秒・任意) `/req04/{学生ID}`

1. 対象企業を選び「アドバイスを生成」
2. 「うまくいっている点 / 改善ポイント / 次回までの行動」が返ることを見せる
3. 「このアドバイスを指導メモに保存」を押す

補足:

- 選考メモ・指導メモがOpenAI APIに送信されること、利用料がかかることは事前に説明する
- APIキー未設定の場合は、**「未設定でも安全に案内する設計」**として画面を見せる(無理に生成しない)

## 6. 企業別の応募状況(45秒) `/req03/companies`

1. 企業ごとの応募者数・面接中・内定・お見送りを一覧
2. 企業名をクリックして志望者を表示

> 「どの企業に人が集まっているか、担任として把握できます」

## 7. CSV出力(30秒)

1. ダッシュボードの「要フォローをCSV出力」を押す
2. Excelで開き、文字化けしないこと・一覧になっていることを見せる

## 8. 締め(30秒)

教員側の3要件との対応を明示する。

| 要件 | 実現した機能 |
|---|---|
| クラス全員の選考状況を把握したい | ダッシュボードの集計・一覧・グラフ |
| 活動が停滞している学生をタイムリーに見つけたい | 要フォローアラート・絞り込み・直近7日の予定 |
| 履歴書添削や面談の個別指導メモを残したい | カテゴリ・次回指導日つき指導メモ、AIアドバイスの保存 |

## デモで困ったとき

- **要フォローが0人**: `app.db` を削除して `py seed.py` を再実行(デモ用データが再生成される)
- **直近7日の予定が空**: 同じく `py seed.py` で再生成(日付は実行日基準)
- **AIが動かない**: APIキー未設定の案内画面をそのまま見せる。通信が不安な場合はAIをデモから外す
- **画面が崩れる**: ブラウザのズームを100%に戻す

## 発表で話すAI開発の比較(メモ)

- 良かった点: 画面+APIを同じ担当がAIと一緒に作れるので速い
- 課題: `db.py` の共通定義を先に固定しないと、結合時にキー名やステータス文字列がずれる
- 改善: 共通定義をプロンプトに必ず貼る、機能ごとに小分けで指示する
